Em uma página

Um produto, dois processos, uma base compartilhada

O repositório reúne coleta de fontes externas, persistência relacional e uma aplicação web. A API e o worker são processos separados; isso não os transforma em microserviços.

Fato

Backend em TypeScript sobre Node.js/Fastify; frontend de busca React/Vite em app-busca, além de páginas HTML/JS/CSS servidas pelo backend. PostgreSQL guarda os dados; Redis sustenta filas/pubsub. Coleta e API compartilham o mesmo repositório e banco.

Interpretação técnica

O desenho favorece adaptação a fontes diversas

Conectores normalizam formatos externos num modelo comum. A fila afasta trabalho lento da resposta interativa, enquanto o banco central facilita busca, atualização e consistência.

Fato

Cobertura parcial medida

Na execução segura desta auditoria: 67,02% linhas no escopo carregado src/**/*.ts. Isso não é cobertura global nem inclui todo código-fonte.

02
Caminho principal

Da origem ao lote exibido

O esquema mostra o fluxo documentado no código; caminhos de detalhe, alertas e atualização em tempo real aparecem abaixo.

Agendamento

src/queue/worker.ts configura concorrência 2, coletas três vezes ao dia, atualização de itens quentes a cada 2 minutos, FENAJU semanal e sondagem diária. O scheduler remove jobs antigos antes de criar novos.

Ciclo de vida dos lotes

Há um fluxo periódico distinto das filas: worker.ts:238–256 verifica encerramento a cada 60 s; :268–290 verifica na origem por padrão a cada 300 s. O README explica que isso evita criar 1.440 jobs/dia para trabalho quase sempre vazio.

Integração não é serviço remoto

API e worker são processos executáveis com responsabilidades distintas, apoiados pelo mesmo código e infraestrutura. Não há evidência aqui de implantação em microserviços.

Decisão guiada por evidência histórica

README registra 3.432 lotes vencidos ainda abertos. A ausência de varredura não prova encerramento: experimento scripts/poc-encerramento.mjs encontrou 19 de 25 candidatos ainda vivos. Regras: prazo e verificação na origem; falha/estado desconhecido permanece indeterminado. São números históricos documentados, não contagem atual.

03
Tecnologias

Stack declarada e forma de execução

Versões abaixo são faixas declaradas nos manifests, não confirmação das versões instaladas em cada ambiente.

Runtime / linguagem
Node.js em módulos ESM; TypeScript no backend e frontend. Também há SQL, Bash e módulos JavaScript.
Compilação
Configuração raiz: strict, alvo ES2022, módulos ESNext, resolução bundler, noEmit; inclui src e scripts. Backend executa TypeScript diretamente com tsx, sem gerar bundle JS. Frontend usa Vite para gerar JavaScript cliente e bundle SSR, com configuração/typecheck separado.
Backend
Fastify 5.12.5 com static 10.1.5, rate-limit 10.3.0, websocket ^11.0.2, formbody ^9.0.0. tsx ^4.19.2; TS raiz ^5.7.3.
Dados e trabalho
pg ^8.13.1 (SQL direto), BullMQ ^5.34.10, ioredis ^5.4.2. Pool PostgreSQL com máximo 10 conexões.
Coleta e serviços
undici ^7.3.0, cheerio ^1.0.0, jose ^6.2.12, nodemailer ^10.0.10, web-push ^3.6.7, sharp 0.35.5.
Frontend
app-busca: React/DOM ^19.2.0, Vite ^8.0.0, plugin-react ^6.1.1, Tailwind ^4.1.18, TypeScript ^5.9.2, Radix, GSAP e Lucide. SPA e bundle SSR.
Infra local
Docker Compose declara PostgreSQL 16, Redis 7 e Keycloak 26 em start-dev. scripts/up.sh aguarda serviços, migra o banco e inicia API/worker no host; compose não empacota a aplicação. É ambiente de desenvolvimento, não receita de produção.
Fato

Há manifests distintos na raiz e em app-busca; não é um monorepo formal configurado com npm workspaces.

Interpretação técnica · motivos possíveis, não histórico de intenção

TypeScript protege contratos compartilhados entre dezenas de conectores. Fastify oferece servidor HTTP com plugins e suporte a testes via inject, sem framework de aplicação mais pesado. React/Vite permite UI cliente e HTML/SSR para páginas que precisam de SEO. SQL direto favorece upsert e índices trigram; BullMQ move coleta demorada para fora do request. Custos: tipos não validam dados em runtime; execução TS sem build exige runtime compatível; cliente+SSR duplicam caminhos de renderização; SQL direto deixa consultas na aplicação; fila/Redis acrescentam operação.

Fato

Configuração de desenvolvimento não é configuração de produção: Keycloak usa modo start-dev e há credencial de fallback; Vite declara host 0.0.0.0, que pode tornar o servidor de desenvolvimento acessível na rede local. Não iniciar/expor serviços como parte deste relatório.

Interpretação técnica

Um tipo canônico reduz diferenças entre parsers e consumidores. Centralizar o filtro global tende a manter a regra consistente independentemente do conector; o limite é que classificação errada nessa etapa afeta todas as fontes.

Fato A normalização está em src/core/normalize.ts; a aplicação de persistência passa por upsertLots(). Este relatório não altera nem reavalia as regras de classificação.

Falta para medir global

Definir escopo com todos os arquivos de produção e frontend, instrumentar também módulos não carregados e executar suíte completa com pré-requisitos controlados. Até lá, cobertura global permanece não medida; isso não significa 0%.

Não foi localizada configuração persistida de cobertura no repositório; a medida acima é desta auditoria e seus resultados estão inline aqui. scripts/teste-classificacao-filtros.ts já protege parte das regras de classificação/filtro; ampliar regressões conforme novas regras ou falhas observadas.

Não foi encontrado CI no repositório; isso não prova ausência de CI externo. npm run typecheck verifica tipos na configuração raiz, não comportamento.

O próximo passo é tornar a qualidade observável

Recomendações pequenas, ligadas às lacunas documentadas — não uma proposta de reescrita.

Como avaliar a próxima rodada

Antes/depois com o mesmo comando seguro, regressões reproduzíveis, comportamento observado por fluxo e documentação atualizada. Assim é possível dizer o que melhorou sem confundir aumento de funcionalidades com melhoria de arquitetura.

Nenhuma arquitetura foi implantada ou modificada por este relatório. O arquivo é documentação estática para leitura local; não instala, inicializa ou publica serviços.
